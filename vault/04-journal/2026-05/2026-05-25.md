## Phase 4.1 — Watchdog → Slack bridge

**Plan gap.** The sprint plan (and the 2026-05-24 spillover item 4.6) assumed a "Netdata MQTT collector" subscribing to the stall topic. Netdata v2.10.3's go.d plugin has **no** `mqtt` module — only `mosquitto` ($SYS broker stats), which can't read arbitrary topics. The watchdog already published `neurosurveillance/watchdog/{camera}/stall` (verified in `recording_watchdog.py`), so the missing half was purely the MQTT → Slack hop. Three options were weighed (mosquitto→curl bridge / StatsD→Netdata alarm / daemon posts directly); chose the **bridge service** — decoupled from the daemon (survives a daemon crash, which is itself an alert condition) and reusable for the reconciler in 4.6.

**Implementation** (all version-controlled):

| Path | Role |
|---|---|
| `backend/scripts/nvr-mqtt-slack.py` | Subscribes via `docker exec mosquitto mosquitto_sub -v`, parses each `topic payload` line, formats, POSTs to Slack. stdlib only. |
| `deploy/nvr-mqtt-slack.service` | systemd unit. `User=skimlab` (docker group), `EnvironmentFile=/etc/nvr-mqtt-slack.env`, `Restart=always` (reconnects when the mosquitto container restarts). `ExecStart` uses the `session-daemon` symlink path. |
| `deploy/nvr-mqtt-slack.env.example` | Template for the secrets env file. |
| `deploy/nvr-mqtt-slack-setup-env.py` | Generates `/etc/nvr-mqtt-slack.env` (mode 0600) by reading the MQTT password from `config.yaml` and the webhook from `health_alarm_notify.conf` — no secret is ever typed or printed. |

**Symlink gotcha.** `/opt/neurosurveillance/session-daemon` → repo `backend/`. The bridge script lives under `backend/scripts/` so its `ExecStart` resolves through the symlink, but the one-time install files in `deploy/` (a sibling of `backend/`) are **not** under the symlink and must be referenced by full repo path. First install attempt failed on the wrong path; fixed.

**Validation.**
- Service `active`, log: `subscribing to ['neurosurveillance/watchdog/+/stall']`.
- Synthetic `mosquitto_pub` of a fake stall → Slack message in ~1s.
- Real E2E: started a `teststall` recording on `pi_cam_0`, `ssh skimlab@192.168.0.11 'sudo systemctl stop go2rtc'`, Slack STALL within ~90s, restored go2rtc, all 4 cameras back to `camera_fps=5.1`. WAL captured `STALL` (`session 554cd949`, `lag_seconds=70.5`).

## Phase 4.2 — ffprobe export-duration sanity check

`daemon._execute_export` (the shared Radiens + manual export path) gained, between the file move and the `EXPORT_COMPLETE` journal write:

- `_probe_duration_seconds(path)` — `ffprobe -show_entries format=duration`; returns `None` on missing/erroring ffprobe (treated as "could not verify", no false partial).
- `_fmt_duration(seconds)` — compact `1.5h` / `45m` / `30s`.
- New constant `EXPORT_DURATION_TOLERANCE = 0.95`. When `moved_to` exists, `probe < 0.95 × session.duration_seconds` ⇒ `export_status = "completed (partial: Xh of Yh)"` + a `logger.warning`. Payload now carries `probe_duration_seconds` and `duration_ok`.

`ffprobe` confirmed at `/usr/bin/ffprobe`. The status update was moved to *after* the probe (was unconditionally `"completed"` before the move). Deployed via daemon restart; startup clean, zero phantoms, reconciler + watchdog threads up. The path will be exercised for real in Tuesday's Phase 5 burn-in.

## Phase 4 — Mosquitto passwd lockdown

## Reconciler check (post-deploy)

Ad-hoc `POST /api/reconciler/run?window_hours=24` after everything:

```
partial_count=1  degraded_count=1  orphan_count=0  stuck_count=0
```

Both findings are the `teststall` E2E session (`554cd949`): PARTIAL at `coverage_ratio=0.498` (105.3s of 211.6s wall — the go2rtc gap), DEGRADED at `stall_count=1`. **This is correct behavior** — the reconciler caught a genuinely anomalous session, validating it end-to-end against a real defect rather than a synthetic one.

The session ages out of the 24h window by the 2026-05-27 run, so nights 2–3 should return to `0/0` absent real sessions. The append-only WAL was deliberately **not** edited to hide the test (that would violate the Phase 2 crash-safety guarantee).
