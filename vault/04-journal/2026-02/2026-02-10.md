### go2rtc Best Practices Audit & Config Update (v5.0 → v5.1)
Ran a comprehensive audit of go2rtc + rpicam-vid config against RPi camera docs and go2rtc docs (via OpenCode). Key findings:

**Validated (already correct):** H.264 via libav, single-line exec, `KillMode=control-group`, direct stdout (no ffmpeg), `--inline`, `--timeout 0`, TCP RTSP in Frigate, Intel QSV decoding, full rpicam-apps.

**Implemented (v5.1):**
- Added `--low-latency` — suppresses B-frames, recommended by RPi docs for streaming on Pi 5
- Added `--intra 15` — 1-second keyframe interval for fast stream startup (Frigate recommended)
- Added `-n` — disable preview window on headless Pi
- Fixed rules table: "Direct hardware encoding" → "Software H.264 via libav/x264" (Pi 5 has no HW encoder)
- Updated [[golden-go2rtc-config|golden go2rtc config]] and public repo `go2rtc.yaml`

**Documentation fixes:**
- [[golden-boot-config|Boot config]]: `gpu_mem=128` annotated as ignored on Pi 5, validation expected value fixed to `gpu=4M`
- [[watchdog-monitoring|Watchdog doc]]: removed 4h periodic restart (causes stream gaps = lost experimental data), added warning against it
- Moved optimization experiment to `completed/` (direct stdout architecture already in production)
- Created [[2026-02-11-mpegts-container-test|mpegts experiment]] for future testing

**Not implemented (correctly rejected):**
- `ExecStartPre=/bin/sleep 60` replacement — intentional for IR LED power spike prevention
- `--libav-format mpegts` — needs controlled experiment first
- `WatchdogSec` — go2rtc doesn't support sd_notify

### Post-Boot Stream Crash
During post-boot validation of the Pi, accessing camera streams caused a full system crash — SSH dropped and Pi became unreachable. After power cycle, all streams tested fine (cam 0, cam 1, both together — no throttling, no errors). Root cause unknown — no persistent journal was enabled at the time. **Fixed:** enabled persistent journaling (`/var/log/journal`) so future crashes are diagnosable.
