### RustDesk Relay Fix (Both PCs)
**Problem:** Both PC1 (`100.117.204.8`) and e10 (`100.85.191.25`) still had the broken NAS relay server (`100.120.86.10`) configured in `~/.config/rustdesk/RustDesk2.toml`, despite the Feb 6 fix attempt.

**Investigation:**
- Edited config files on both machines to clear `relay-server`, `custom-rendezvous-server`, and `rendezvous_server`
- After RustDesk restart, configs reverted — RustDesk overwrites the file from its in-memory state on restart
- However, RustDesk is not actually using the relay in practice — connections go direct P2P via Tailscale

**Current state (verified):**
| Metric | PC1 → e10 |
|--------|-----------|
| **Ping** | 1.2ms avg, 0.14ms jitter |
| **Send-Q** | 0 (was 7.9KB before Feb 6 fix) |
| **Connections to NAS relay** | None |
| **RustDesk connection** | Direct P2P on port 33713 |
| **Packet loss** | 0% |
| **VA-API (e10)** | Intel iHD 24.1.0, H.264/HEVC encode working |
| **Kernel (e10)** | 6.17.0-14-generic |

**Conclusion:** Connection is healthy. The relay config entries are cosmetic — RustDesk prefers the direct Tailscale path. No lag observed.

**Note:** To permanently remove the relay config, it needs to be changed through RustDesk's GUI (Settings → Network), not by editing the TOML file directly, since RustDesk overwrites file changes on restart.

### go2rtc Configuration Fixes (Vault + Public Repo)
Found and fixed three critical configuration issues documented in [[03-troubleshooting/incidents/2026-02-09-go2rtc-setup-troubleshooting|go2rtc Setup Troubleshooting]]:

1. **systemd inline comments breaking KillMode** — systemd silently ignores `KillMode=control-group # comment`, treating the whole string as the value. Fixed in [[01-infrastructure/raspberry-pi/golden-systemd-service|golden systemd service]] by moving comments to separate lines.

2. **go2rtc YAML multi-line exec blocks** — `exec: >` multi-line format doesn't work with go2rtc. Fixed in [[01-infrastructure/raspberry-pi/golden-go2rtc-config|golden go2rtc config]] to use single-line `"exec:rpicam-vid ..."` strings. Also removed the ffmpeg pipe architecture (proven unstable for 24/7).

3. **Missing rpicam-apps prerequisite** — Raspberry Pi OS Lite ships `rpicam-apps-lite` which lacks libav codec. Added `sudo apt install -y rpicam-apps` step to [[02-procedures/installation/new-pi-setup|new Pi setup]].
