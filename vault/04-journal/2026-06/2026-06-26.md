# 2026-06-26 — 8-channel standard; Setup A won't enumerate; Setup B still floating

> [!warning] TL;DR
> Switched the whole rig to the **8-channel slip-ring / 8-pin tether** standard and tried the **grounding-busbar** GND fix on two headstages. **(A) The single-mouse headstage won't enumerate** — root cause still open, isolated to the SPI *signal* path. **(B) The 2-mice+ECG headstage enumerates but the busbar ground is NOT working** — animals still floating (10/12 channels railed). Both carry to tomorrow.
> ⚠️ **The "cold joint on the GND pad" theory below was DISPROVEN on [[2026-06-27]]** — the real cause was that the *animal itself* had no ground tie. Read this day's Setup-B conclusion in that light.

## Standardization decision
**8-channel system is now the standard everywhere.** Swapped tether → 8-pin slip-ring socket. New grounding = **animal ground wire → busbar → one wire → C3410 `GND` pad** (the animal ground is no longer on a signal pad — the old defect).

## Setup A — single-mouse headstage: NOT DETECTED 🔴 (open)

One mouse, same headstage as before, on the **second SPI socket** of the SAdpt-XDAQ-OM12 bridge. Only physical change vs the last-working 06-22 state: soldered a **`GND` socket onto the C3410 `GND` pad** + wire to busbar, swapped to the 8-pin tether. Map: `0` EEG red, `1` EEG black, `2` EMG yellow, `3` EMG blue, **green = animal ground → busbar**.

**Symptom:** `port_num_channels = {}`, `priSigs=0` on every scan. Never enumerates.

**Eliminated today (exhaustive):**
- ✅ Allego mode correct (`XDAQ_ONE_REC`; it *did* silently revert to SmartBox Pro once after a relaunch → restored).
- ✅ XDAQ core healthy — USB SuperSpeed (`151f:0130`), FPGA configured, onboard I/O enumerates (`Fs=30000`).
- ✅ Bus power present — DMM VDD↔GND while streaming = **3.57 V** (matches 06-19; top of Intan 3.2–3.6 V spec).
- ✅ No VDD↔GND short (open on 2k range).
- ✅ Ground rewire excluded — tested **bare headstage, SPI cable only, ground fully disconnected**, correct mode, power confirmed → still `priSigs=0`. So the new busbar is NOT what blocks detection.
- ✅ Swapped headstage, both C3026 cables, both SAdpt adapters, ports 1 + 4, full power-cycle, PC restart.

**Where it stands:** power-good + correct-mode + bare-SPI + everything-swapped + still `priSigs=0`. SPI power+ground pins work (3.57 V) → fault is in the SPI **signal** path (SCLK/CS/MOSI/MISO) — either this headstage's SPI Omnetics (a bent/recessed signal pin) or the XDAQ SPI subsystem on **that** bridge socket.

> [!note] Strong clue — it's socket-specific
> Setup A failed on the SAdpt's **second** SPI socket; Setup B enumerates fine on the **other** socket of the same bridge, same XDAQ, same mode. → not XDAQ-core-wide; points at the Setup-A headstage's SPI connector **or** that specific SAdpt socket / HDMI path. (This becomes the **socket-swap test** that runs through to [[2026-06-29]].)

**Tomorrow — decisive test** (bare-SPI, power-confirmed): spare headstage on the same socket → detects ⇒ in-use headstage's SPI connector damaged; still `{}` ⇒ that SAdpt socket/HDMI → swap to the known-good socket to confirm, else vendor (KC Kong / Kontex). Magnifier-inspect the suspect Omnetics.

## Setup B — 2 mice + ECG headstage: DETECTED, grounding bus NOT working 🔴

Separate headstage, **2 mice**, on the other SPI socket. Detected: **Port A, 32 ch, `XDAQ_ONE_REC`, streaming.** Per mouse: EEG + EMG + ECG. Map: `0` EEG+ red, `1` EEG− black, `2` EMG+ yellow, `3` EMG− blue, `4` ECG+ green, `5` ECG− brown, **orange = GND → bus**; Mouse 2 from native 8.

**Raw signal metrics** (raw first, `np.NAN` shim):

| native | `D/n` | signal | RMS µV | pk-pk µV | verdict |
|---|---|---|---|---|---|
| 0 | D/1 | M1 EEG+ | 2964 | 12486 | 🔴 railed |
| 1 | D/2 | M1 EEG− | 159 | 1511 | ok |
| 2 | D/3 | M1 EMG+ | 289 | 1412 | ok |
| 3 | D/4 | M1 EMG− | 2498 | 12229 | 🔴 railed |
| 4 | D/5 | M1 ECG+ | 2254 | 12642 | 🔴 railed |
| 5 | D/6 | M1 ECG− | 2505 | 12013 | 🔴 railed |
| 8 | D/9 | M2 EEG+ | 2266 | 9899 | 🔴 railed |
| 9 | D/10 | M2 EEG− | 2282 | 12088 | 🔴 railed |
| 10 | D/11 | M2 EMG+ | 2295 | 9626 | 🔴 railed |
| 11 | D/12 | M2 EMG− | 1044 | 8966 | 🟡 elevated |
| 12 | D/13 | M2 ECG+ | 2806 | 11393 | 🔴 railed |
| 13 | D/14 | M2 ECG− | 1049 | 10082 | 🔴 railed |

- Amp window ±5 mV. **10/12 channels railed at 10–12.6 mV = animals floating.** Same fingerprint as pre-grounding 06-22.
- **Both mice railed together** → they share one tie (bus → `GND` pad → chip GND). Everything railing ⇒ the common ground tie isn't reaching the animals.

> [!caution] This day's conclusion was WRONG (superseded [[2026-06-27]])
> We concluded the busbar wasn't reaching chip `GND` → prime suspect "**cold joint** on the freshly-soldered `GND`-pad socket." **End-to-end beep tests on [[2026-06-27]] killed that** — the busbar→chip-GND path was fine. The real cause: **the bus grounded the headstage/system, but the animal itself was never tied to it** → the animal floated. The fix was an animal-ground electrode (dura pin → green → bus), not a re-flow.

**Tomorrow (as planned that day):** DMM-continuity the ground chain (busbar screw ↔ `GND` pad ↔ chip GND ↔ animal-ground wire), each link ~0 Ω. *(This is what disproved the cold-joint theory.)*

## Tools / SDK notes
- Live probe: `/opt/neurosurveillance/venv/bin/python -c "from radiens import AllegoClient; print(AllegoClient().get_status().port_num_channels)"`.
- Port-scan truth: `grep priSigs ~/.local/state/radiens/logs/allegoserver.log | tail` — sweeps all ports at once; `priSigs=0` = no chip answering anywhere.
- Metrics need `np.NAN=np.nan` (radiens 4.0.0 + NumPy 2.x). Array `(1,32,6)`: RMS, NOISE_UV, MAX_MIN_DIFF_ABS, SNR, EVENT_RATE, EVENT_MEAN; `MAX_MIN_DIFF_ABS` ≈ 10–12 mV = railed.
- `HAL:cc22 "unable to send to listener"` in the log = MQTT subscriber noise, unrelated to SPI/detection — ignore.
