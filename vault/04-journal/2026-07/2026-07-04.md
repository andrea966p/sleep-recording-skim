# 2026-07-04 — First real 8-mouse setup; C3442 2nd-headstage channel offset nailed (+32, not +16/+28); custom sensor dropped for passthrough

> [!success] TL;DR
> All 8 mice connected (1 mouse/headstage, 2 headstages/port via C3442, 4 ports A–D, each **64 ch**, fs 1000). Hit a channel-selection mismatch: the pre-built custom sensor relabeled channels by site and the 2nd-mouse pick on Port A landed on **empty floor channels**. Verified live where the real signal sits and switched to **passthrough on all ports**. Full ready-to-record guide: [[eight-mouse-acquisition-setup]].

## The finding — 2nd headstage on a C3442 port = native +32

Per port (64 ch), each RHD2216 reserves a 32-ch MISO slot:
- **HS-A real = natives 0–15** (pads 0–3 → **0,1,2,3**); HS-A empty floor = 16–31.
- **HS-B real = natives 32–47** (pads 0–3 → **32,33,34,35**); HS-B empty floor = 48–63.

So each mouse's 4 electrodes (EEG+, EEG−, EMG+, EMG−) = **`/1,/2,/3,/4`** (HS-A) and **`/33,/34,/35,/36`** (HS-B). Confirms the stress-test `A/34` reading; kills the earlier "+16" guess.

### Live proof (radiens SDK, read-only, streaming)
Per-channel pk-pk on the selected set:
- `A/pri_28–31` (what got picked for M2 on Port A) = **quiet floor ~200 µV pk / 40 rms** → empty.
- `B/pri_96–99`, `C/pri_160–163`, `D/pri_224–227` (= native 32–35) = **railing ~11 000 µV** → real channels (open contact).

Port A was the odd one out because it had the custom sensor loaded (site relabel); B/C/D were passthrough and got the right block.

## Fix applied
- **Dropped the custom `dual_mouse_c3442` sensor** (site numbering collided with the natural layout; for 4 ch/headstage it only adds a trap). Marked DEPRECATED in [[signal-mapping-guide]]-family docs and in [[eight-mouse-acquisition-setup]] §3.
- **Passthrough on all 4 ports** (Headstage `Passthrough 64`, Probe `Default 8x8`). Label = native + 1 everywhere.
- **Selection block, every port:** `/1,/2,/3,/4` + `/33,/34,/35,/36` = 32 channels = 8 mice.
- Port A re-selection: deselect `/29–/32`, select `/33–/36`.
