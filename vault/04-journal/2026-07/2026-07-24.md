# 2026-07-24 — Friday — DAQ comparison goes 3-way; Intan added; per-port record control overturned

Scale-up work. The 2-way XDAQ vs Open Ephys comparison was superseded by a **3-way** one that adds **Intan direct**, and a long-held belief about recording control was overturned by reading the API docs properly.

## Built today

- ⭐ [[2026-07-24-daq-32-mouse-final-comparison]] — **the decision doc.** 3-way comparison scoped to 32 mice, with priced bills of materials for each ecosystem and two scenarios each (isolation-first vs density-first). Supersedes [[daq-ecosystem-comparison-xdaq-vs-openephys]], which is now marked `superseded`.

## Headlines

- **Intan direct enters the comparison** as a third ecosystem. They make the RHD chips all three systems use, and they publish full list pricing, unlike Kontex.
- **The 2-headstages-per-port question was settled** from Intan's own datasheets: the dual-headstage adapter (C3442) puts two independent chips on the port's two MISO lines, so **two separate animals per port is real**. The caveat is that they share the port's ground.
- 🔴 **OVERTURNED: "Allego can only do one global start/stop".** The radiens v4.0 Python API documents **per-port** control — `start_recording(port=...)`, `stop_recording(port=...)`, and `RecordingConfig.split_files_by_port`. Updated [[multi-user-independent-recording-schedules]] accordingly.
  > ⚠️ **This was itself corrected on 2026-07-28.** Per-port is not per-animal: the port enum caps at 8, a ONE+ has 4 physical ports, and 16 animals hang off Port Expanders. See [[daq-research-findings-primary-sources]].
- **Separated two capabilities that are constantly conflated:** separate *files* per animal (a data-layout question) versus independent *start/stop timing* per animal (a scheduling question). A system can have the first without the second.
