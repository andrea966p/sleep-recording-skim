# 2026-09-14 — per-port rig layouts

Andrea asked for the rig layout to be declared per port instead of picked from three
fixed presets, and for people to be able to add their own recording settings without
editing YAML over SSH.

## What I got wrong, and the correction that mattered most

I read the vault's mixed layout `A:64@0 B:32@64 C:64@96 D:64@160` as evidence that
ROLES differ per port, and designed for that. Andrea corrected it mid-build:

> "there will never be mice connected to the rig with different configuration at the
> same time. When someone records, the mice have all the same settings. What changes
> is just the amount of mice connected."

That layout is a **splitter** difference with identical roles throughout. Conflating
the two inflated the design — it killed the per-port setting dropdowns entirely.

What survived was needed anyway: `slot_bases` was GLOBAL, so the old model could not
express "splitter on A and C, none on B and D" at all. Per-port chip counts are
exactly that.

## The bigger correction: a false line I wrote on 2026-09-13

I had written, twice, that no unipolar headstage has ever been connected to this rig.
**It has** — 2026-08-05, port A, all six sites live at once with clean physiological
signal on each, the only time this project has managed that.

The error was not cosmetic. That page is the source of the `/18`–`/23` site map AND of
the measurement that forbids deriving a floor for it. A wrong disclaimer was hiding the
evidence the whole feature depends on.

And it led me to record the wrong REASON for the unipolar layout having no QC floor. I
had written "the floor model does not describe these offsets" — a shape mismatch. The
truth: an RHD2132 has **32 real inputs**, so a floor *could* be derived from its ~26
unused ones, and must not be, because those inputs are **tied to ground** (median
0.17 MΩ, measured). A floor from them flatters the control and condemns every animal.

🔑 Shape-mismatch invites the next person to fix the shape and derive a floor from
`/24`–`/32`. Evidence-absent does not. The config now records the second, in a field of
its own, and the console refuses to save such a layout without a reason.

That also exposed a live contradiction: `criteria.py:80` stated the 16 real channels of
an RHD2216 as a universal law, which is false for the unipolar chip — the repo held two
incompatible claims about the same six sites.

## The check that makes the feature worth having

Allego already reports what each port enumerated. The console now predicts the same
number from the declaration and compares:

    port C: declared no splitter with RHD2216 bipolar, which enumerates 32 channels
    -- but Allego reports 64. Either the splitter state is wrong or the headstage is
    not the one declared.

Start disabled, and the API refuses it independently of the page. Verified both ways
against the live rig. A wrong declaration used to be a discovery made after the animals
were done.

## Three bugs the work surfaced

- `ports_used or PORTS` — an **empty** tuple is falsy, so declaring NO ports in use
  silently expanded to all four, and the enumeration check then compared against ports
  nobody had touched. Caught by a refusal test, not by review.
- The layout dropdown was independent state and on first load displayed "4 mice,
  unipolar LFP" over a rig declared as 8-mouse EEG/EMG. Harmless functionally, and
  exactly the kind of label somebody later believes. It is now derived.
- `UNJUDGEABLE` was missing from all three verdict tables, so it rendered grey with "?"
  — **the same glyph as INSUFFICIENT**, right under the comment insisting they must
  never read alike. Live on real cards since August.

## The settings panel, and why it writes a second file

`users.yaml` carries the provenance this project runs on. No YAML dumper in the standard
library round-trips comments, so a machine rewriting it would strip every one. Additions
from the form go to `custom.yaml` instead; `git diff` then shows what a person wrote
versus what a form generated. Verified through the browser: after adding and deleting a
setting, `git diff users.yaml` is empty.

The form previews the consequence rather than the input — the exact sites for both
animals on a split port, and whether a QC floor will exist. Someone who meets "no QC
bundle will ever be produced for this layout" at save time can change their mind. At
09:00 on the morning of a run, they cannot.

## What I could not prove

`test_criteria_regression` and `test_ladder_verdicts` **skip and exit 0** — the pinned
`floor.n_samples == 953904` never ran, so the best backward-compatibility tripwire this
repo has was unavailable. Substituted a real one: `compute_features` over 30 minutes of
`allego_1__uid0909-21-17-52` under the tagged pre-change code and under the branch,
dumping every per-chip floor. **Byte-for-byte identical**, both role sets.

## 🔴 The bug this run existed to find

The strip refused the file it had just been handed:

    REFUSED: the rig looks busy: allego_0__uid0914-10-50-56_data.xdat was written
    4 s ago. Refusing to compete with a live recording for the same disk.

`--require-idle` uses mtime, and **mtime cannot tell "stopped four seconds ago" from
"being written right now."** Every strip follows a stop by seconds, so the guard
refused its own input.

The part worth keeping: **this had never been seen because the QC bundle runs first.**
On the 24 h S-SL run that takes tens of minutes, so the mtime aged past the 120 s
window *by accident* and the strip proceeded. The protection on every real run so far
was incidental, not designed. Five minutes of bench data computed QC in two seconds and
the guard fired at once — invisible on long recordings, certain on short ones.

Fixed: the source is judged by whether anything is still **appending** to it (measure,
wait, measure). Other recordings keep the mtime rule, because for them recent IS the
danger. All three behaviours are now pinned by a test, including the one that matters —
a still-growing source is refused, naming the byte counts.

Also fixed: the settings panel called `boot()` to refresh after a change, and no such
function exists, so the main form kept showing the old list until a reload.

## What this run did NOT prove

All four ports physically carry splitters, so a **mixed** rig could not be declared and
recorded — the enumeration check would correctly refuse it. Mixed layouts remain covered
by unit tests plus the live refusal demonstrated earlier. Recording one properly needs a
splitter physically removed.

The bench folder `20260914_BENCH0914_BSR` is test data sitting in andrea's NAS folder,
with fake mouse IDs `BENCHA1/BENCHC2/BENCHD1`. Delete it whenever.
