# 2026-09-29/30 — the SKIM NAS is organised by mouse, as CSV, cut to 24 h windows

## What happened, shortest version

- **The recording workflow's output changed.** A run now arrives as **one CSV per mouse** in
  `02_Data_Sleep/<user>/<batch>/<Baseline|Recovery>/<YYYYMMDD>_<MOUSEID>_<B|R>/`. It used to be
  one folder per run in `03_Data_Mouse/` holding the stripped xdat.
- **The eight canonical recordings were rebuilt** into that tree, each cut to its analysis
  window: 64 mouse folders, 291 GB, all verified.
- **The verdict ladder was re-run on exactly those windows.** Scoreable at both timepoints:
  HLBWSD08, HLBWSL24 and HLBSSL33, plus HLBSSL31 and HLBSSL35 on stage 3. S-SD has none.

## Why

On the NAS, `HLBWSD_BSR` sat beside `BSR-2`, and there were two `HLBSSD_BSR` folders, and nobody
could say which was which. The reasons:
- **W-SD:** the 08-19 baseline was stopped at 17:16, when B1 chewed its tether, and restarted
  9 min later. That made two files.
- **S-SD:** the 08-26 folder is the B1-swap re-record, a different recording.

Andrea also asked for four changes:
- **codes:** B and R instead of BSR and RSR;
- **format:** a per-mouse CSV with the timestamps in the same file, which is what the analysis
  pipeline reads, not the xdat;
- **location:** the files in `02_Data_Sleep`;
- **layout:** the tree organised by user → batch → condition → mouse.

## What was built

Details in [[per-mouse-csv-format]].

- **The CSV follows Diane's reference MATLAB export.** The reference is
  `03_Data_Mouse/diane/20260816_H5A251F0209_A01__BSR.mat`, read with h5py.
  - Columns: `timestamp_raw,timestamp_sec,datetime_kst,EEG,EMG`.
  - `timestamp_raw` is Allego's device counter, copied as-is. `timestamp_sec` starts at 0.
  - Values are µV to 3 decimals, and every one is a multiple of the amplifier's 0.195 µV step.
- **The pipeline is now QC → STRIP → EXPORT → UPLOAD.**
  - `eeg-emg-analysis/export/per_mouse_csv.py` reads the stripped file. It maps mice to columns by
    site label and refuses any label that is missing or ambiguous.
  - After writing, it re-reads each CSV: row count, first and last timestamp, and 1000 spot rows
    against the xdat.
  - The uploader re-hashes the file. After every CSV of a run has verified, the local CSVs are
    deleted.
- **Console and config changes.**
  - A batch name is required.
  - The only types are Baseline (B) and Recovery (R). The `sd` type is gone, because the batch id
    already carries it.
  - The UI preview shows each mouse's destination path.
  - The NAS root comes from `config/users.yaml` (`nas.root`), which is now actually read.
- **Tests:**

  | suite | passed |
  |---|---|
  | naming | 27 |
  | run states and scheduler | 33 |
  | layout | 33 |
  | settings | 24 |
  | CSV exporter | 22 |
  | stripper | 28 |

  Each suite was checked to have actually run its cases.
- **One bug found by the tests:** the spot check let a NaN in the xdat pass against a number in
  the CSV. Fixed.

## Worth knowing

- **Excel and LibreOffice cannot open these CSVs usefully.** They stop at 1,048,576 rows, about
  17 min of a file that holds 86.4 M rows. LibreOffice's Text Import also remembers its last
  separator, which is why a file showed up as one column. Read the files in code.
- **Tailscale SSH to the workstation is in check mode**, and it hangs silently waiting for a
  browser re-auth. Diane's .mat was copied to the NAS instead.
- **`allegoserver` has been spinning a core for 6 days**, the known runaway thread after the GUI
  closes ([[allegoserver-runaway-thread-thermal]]). It did not affect today's work.
