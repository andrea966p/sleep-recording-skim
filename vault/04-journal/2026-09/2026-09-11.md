## What happened

**The SKIM Lab NAS is up.** `SKIM_NAS` over Tailscale, SMB only — SSH is closed on every port I
tried. Mounted at `/mnt/skimnas` via a systemd automount, `vers=3.1.1` first try. All five member
folders present under `03_Data_Mouse`. 1.3 TB free of 7.0 TB.

**Three measurements that changed the design**, each of which invalidated something I had written:

1. **The path is DIRECT, not relayed.** `tailscale ping` said `via DERP(tok)` and I built a whole
   throughput risk analysis on it — estimating days for a bulk transfer. Hole-punching simply had
   not finished. It is 1 ms, same campus, **94 MB/s write**. Re-ping before concluding a peer is
   relayed. The entire risk analysis went in the bin.
2. **Reading a file back over CIFS verifies your own page cache.** 1538 MB/s on a just-written
   file. After `posix_fadvise(DONTNEED)`: 89.8 MB/s and a real hash. A verification that skips the
   fadvise is a gate that cannot fail. Tested adversarially by flipping a byte **on the NAS** — the
   next run caught it and re-uploaded.
3. **`np.memmap` made the stripper's peak RSS 9.26 GB on a 5.26 GB file.** Every touched page is
   resident. Chunked `np.fromfile(offset=)` instead: **186 MB, and 25% faster**.

**The bench test found something better than what it was testing for.**
`set_recording('off')` works fine — my "never called in this repo" flag was true of the code but
misleading about the risk. The real finding: **the `.xdat` file size reports 0 for a full 30 seconds
after a perfectly healthy start**, then jumps to 31 MB. My 11-second growth check declared a working
recording dead, and because it asserted before its stop call it **left the rig recording**. Both
lessons are now in the code: two-stage verification, and a `finally` that stops the recorder.
Full write-up: [[05-experiments/completed/2026-09-11-allego-control-bench-test]].

**A side effect I caused and undid:** `ConfigRecording` is persistent, so the test left Allego
pointed at a scratch directory I then deleted. Restored to `{RAW_ROOT}` immediately. Anyone
redirecting the recording path must restore it, and `get_status().recording.path` cannot be used to
check because it reports the calling process's working directory.

**Retraction filed.** `radiens 4.0.0` has **no `start_recording(port=…)`** — 25 public methods,
none of them it, and `split_files_by_port` exists only in the protobuf. The 2026-07-24 "DOC-VERIFIED"
update on [[02-procedures/multi-user-independent-recording-schedules]] describes a doc build we do
not have installed. 4.0.0 **is** the latest stable, so this is not being behind. Recording is global;
per-user separation only ever happens by stripping afterwards.

**A bug the browser caught.** Flask sorts JSON keys, so the console's owner dropdown defaulted to
`ahyeon` — whoever sorts first. On a shared rig that is exactly how one person's run lands in
another's folder. There is now no default owner at all.
