**B2 is the interesting failure**: its EEG is genuinely good (92.4% usable, 261 min block) but its
EMG electrode is open at 535.8 µV, and WAKE is separated by an Otsu cut on log EMG RMS. So the
pipeline correctly returns no states. Its EEG columns stay valid for spectral work. **I did not
invent an EEG-only stager** — that exists in the literature but is not implemented or validated
here, and an unvalidated staging algorithm is how a confidently wrong result gets made.

## Two operational things worth keeping

⚠️ **`nohup` is not enough for a long job.** The first export died leaving a **0-byte `.mat`**
because the launching shell timed out and SIGTERM'd the process group. `nohup` guards SIGHUP only.
**Use `setsid`.**

⚠️ **Correction to something I said yesterday.** I claimed the pipeline "had been unrunnable". That
is **wrong**: `/usr/bin/python3` has numpy 1.26.4 + scipy 1.11.4 and runs it fine, exactly as
[[eeg-analysis-problems]] already said. What is true is that
`~/eeg-analysis-venv` has numpy 2.5, and numpy 2.0 removed `np.trapz`. Stages 1 and 3 now bind
`np.trapezoid` when present, so the pipeline runs on **either** numpy. 🔑 **`radiens` lives only in
the daemon venv and analysis does not need it: recording → daemon venv, analysis → system python3.**
