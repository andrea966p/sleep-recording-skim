## Work Log

### Unexpected Camera Recording — Root Cause Found

Cameras were found recording even though no session was started. Investigation traced the cause:

**Root cause:** On 2026-03-30 at 11:05, `aptdaemon` (GNOME Software Center) upgraded `docker-ce` from `29.3.0` to `29.3.1` and `docker-ce-cli` to `29.3.1`. This restarted the Docker daemon, which restarted all containers (restart policy: `unless-stopped`). When Frigate started, it loaded `record.enabled: true` from the config file — the per-camera `enabled: false` state set by MQTT is **in-memory only** and does not persist across restarts.

**Timeline (Mar 30):**
| Time (KST) | Event |
|-------------|-------|
| 11:05 | `aptdaemon` upgraded docker-ce 29.3.0 → 29.3.1 |
| 11:06:17 | Docker service stopped/restarted |
| 11:06:41 | Frigate started → all 4 cameras recording (`record.enabled: true` from config) |
| 15:22 | User opened Frigate UI |
| 15:39 | Recordings turned off for all cameras via daemon |
| 15:51-15:52 | System rebooted (kernel 6.17.0-14 → 6.17.0-19), cameras recorded again |
| 17:45 | Recordings turned off again for all cameras |

**Why the Mar 9 fix didn't work:** The Docker package blacklist was added to `/etc/apt/apt.conf.d/50unattended-upgrades`, which only blocks the **unattended-upgrades** service. The Mar 30 upgrade was done via `aptdaemon` (GUI software updater), which **ignores** that blacklist entirely.

**Proper fix:** Use `apt-mark hold` to pin Docker packages across ALL upgrade methods:
```bash
sudo apt-mark hold docker-ce docker-ce-cli containerd.io docker-compose-plugin docker-buildx-plugin docker-ce-rootless-extras
```

> [!warning] Lesson Learned
> `50unattended-upgrades` blacklist only covers `unattended-upgrades`. The GNOME Software Center (`aptdaemon`) and manual `apt upgrade` bypass it. Only `apt-mark hold` blocks all paths.

### Netdata Alert Configuration

Netdata v2.9.0 was installed on 2026-03-27 but shipped with **227 default alerts** — most completely irrelevant (Ceph, Kubernetes, Redis, Beanstalkd, etc.). Configured custom alerting:

**Step 1: Silence all defaults**
- Added `enabled alarms = nvr_*` to `/etc/netdata/netdata.conf`
- This single line filters out all 227 defaults, loading only alerts prefixed with `nvr_`

**Step 2: Define NVR-specific alerts**
- Created `/etc/netdata/health.d/nvr-alerts.conf` with 9 alert definitions
- 9 definitions expand to **16 active instances** (templates instantiate per disk mount and per container)

Alerts defined:

| Alert | Threshold | Why |
|-------|-----------|-----|
| `nvr_cpu_high` | >85% warn, >95% crit (10min avg) | Frigate ffmpeg/detection overload |
| `nvr_cpu_iowait` | >40% warn (10min avg) | Disk write bottleneck from recordings |
| `nvr_ram_usage` | <10% avail warn, <5% crit | OOM risk — Frigate uses significant RAM |
| `nvr_swap_usage` | >50% warn | Memory pressure degrading performance |
| `nvr_disk_space` | >90% warn, >95% crit | Recording storage filling up |
| `nvr_disk_inodes` | >90% warn, >98% crit | Inode exhaustion (many small files) |
| `nvr_container_unhealthy` | Any unhealthy | Docker health check failures |
| `nvr_container_down` | Frigate/Mosquitto/Kuma exited | Critical container stopped |
| `nvr_cpu_temperature` | >85°C warn, >95°C crit | NUC thermal throttling |

> [!info] Template vs Alarm
> Most alerts use `template` (matches all charts with same context — e.g., `disk.space` creates one alert per mount point). Temperature uses `alarm` (matches one specific chart) because the Package ID 0 sensor is the only one that matters for throttling.

**Step 3: Slack notifications**
- Created `/etc/netdata/health_alarm_notify.conf`
- Disabled all notification methods (email, Telegram, Discord, etc.) except Slack
- Uses the **same Slack webhook** as Uptime Kuma — both post to the same channel
- Tested with `alarm-notify.sh test` → 2 test messages received
- Real-world test: stopped Mosquitto → WARNING notification → started Mosquitto → CLEAR notification

**Final state:** 16 alerts, all CLEAR, Slack notifications confirmed working.

See [[nvr-alerts-config|NVR Alerts Golden Config]] for the full config reference and management guide.
