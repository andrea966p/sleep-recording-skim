### Incident

Setting up `.stignore` on the private repo led to a destructive Syncthing accident: I `rm -rf`'d this PC's partial sync data while the folder was still a sendreceive member (paused, but still tracked). On unpause, the deletion got announced to `e10ubuntu`, which dutifully deleted the actual source files. `.stignore` saved the build artifacts but **not** the source.

Damage on `e10ubuntu`: full `.git/`, all `backend/*.py` (except `__pycache__`), all `frontend/src/...` source, and the entire dirty WIP working tree (10 modified + 3 untracked files).

Recovery succeeded via Claude Code transcripts at `~/.claude/projects/-home-skimlab-Monitoring-project/`, which had captured every WIP file via Read/Edit/Write tool calls (especially the **subagent** transcripts under `<session>/subagents/agent-*.jsonl`, where Explore agents had done full reads of all backend modules on 2026-04-01).

For `backend/storage_monitor.py` (untracked, no remote, no full Read), used `pycdc` against the surviving `.pyc`. Three methods didn't decompile cleanly due to unsupported Python 3.12 opcodes; reconstructed best-effort from the `dis` disassembly with `TODO` markers.

Full incident report: [[2026-04-29-syncthing-deletion-and-recovery|2026-04-29-syncthing-deletion-and-recovery.md]]
