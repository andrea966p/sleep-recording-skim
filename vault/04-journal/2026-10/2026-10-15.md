# 2026-10-15: ahyeon's 30 h unipolar run lost port B and port C; stopped after 13 min

Andrea checked the rig at ~09:12 over RustDesk: headstage B was gone and every channel of mouse C looked the same
("mirrored"). Andrea stopped the recording in Allego and restarted Allego. Question to Claude: did anything in the
10-14 console changes (unipolar map, cancel button, watchdog auto-arm, strip GPIO flag) affect the recording?
Andrea's own reading: the mice loosened the unipolar headstages. The SPI cable runs straight to the XDAQ with no
counterbalance arm or commutator.

**Verdict: hardware, not software.** Nothing in the console or Allego logs shows software acting on the ports.

- Every electrode carries one large common signal with mains on it. This is the pattern of a **lost reference or
  ground contact**, which points to the connector at the head, not to the electrodes.

## Code audit of the 10-14 changes

- **Cancel button**: `/abort` changes the run's state only, and is refused for any run that has started. It makes no Allego call.
- **Watchdog**: reads `get_status()` only.
- **Map, strip and uploader changes**: run after the recording only.
- **Console backend**: its only Allego writes are `set_streaming` and `set_recording` on or off at the scheduled times.
- Nothing in software can drop a headstage from the SPI scan.

## Gap found

The scheduler does not compare the live enumeration with the declared layout at start. A headstage lost 9 h before
the run went unreported, and the run recorded 2 of 3 mice in silence. Fix in progress in a separate session:
check at start, record the mismatch on the run, show it in the UI, send an ntfy alert, and **still start** the run
for the mice that are connected.
