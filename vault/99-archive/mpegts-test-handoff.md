## What to Do: Execute the MPEG-TS Container Test

The experiment doc is at: `05-experiments/active/2026-02-11-mpegts-container-test.md`

The test changes ONLY `--libav-format h264` to `--libav-format mpegts` in the go2rtc exec strings.

### Current production config (v5.1, deployed on Pi)

```yaml
streams:
  pi_cam_0: "exec:rpicam-vid -n --codec libav --libav-format h264 --width 1024 --height 768 --framerate 15 --bitrate 1500000 --inline --intra 15 --timeout 0 --camera 0 --level 4.1 --profile high --low-latency --output -"
  pi_cam_1: "exec:rpicam-vid -n --codec libav --libav-format h264 --width 1024 --height 768 --framerate 15 --bitrate 1500000 --inline --intra 15 --timeout 0 --camera 1 --level 4.1 --profile high --low-latency --output -"
```

Config file on Pi: `/opt/go2rtc/go2rtc.yaml`

### Execution Steps

#### Phase 1: Baseline Snapshot (~5 min)

SSH to Pi and capture current h264 metrics while streams are active:

```bash
ssh skimlab@192.168.0.11
```

Trigger streams so rpicam-vid processes are running:
```bash
curl -m 10 "http://localhost:1984/api/stream.mp4?src=pi_cam_0" -o /dev/null &
curl -m 10 "http://localhost:1984/api/stream.mp4?src=pi_cam_1" -o /dev/null &
```

Record baseline:
```bash
vcgencmd measure_temp
vcgencmd get_throttled
free -m
ps aux | grep rpicam-vid | grep -v grep
cat /proc/loadavg
```

Check Frigate is recording (run on PC 2 locally, no SSH needed):
```bash
curl -s http://localhost:5000/api/stats | python3 -m json.tool
```

#### Phase 2: Switch cam 0 ONLY to mpegts

On the Pi:

```bash
sudo cp /opt/go2rtc/go2rtc.yaml /opt/go2rtc/go2rtc.yaml.v5.1.h264.bak
sudo nano /opt/go2rtc/go2rtc.yaml
```

Change ONLY `pi_cam_0` line: `--libav-format h264` -> `--libav-format mpegts`
Leave `pi_cam_1` as `h264` for comparison.

Restart (note: there is a 60s ExecStartPre=/bin/sleep 60 delay):
```bash
sudo systemctl restart go2rtc.service
sleep 70
sudo systemctl status go2rtc.service
curl -s http://localhost:1984/api/streams
journalctl -u go2rtc.service -n 30 --no-pager
```

Watch for MPEG-TS parsing errors:
```bash
journalctl -u go2rtc.service -f
```

### Rollback

If anything goes wrong:
```bash
sudo cp /opt/go2rtc/go2rtc.yaml.v5.1.h264.bak /opt/go2rtc/go2rtc.yaml
sudo systemctl restart go2rtc.service
```

### Success Criteria (from experiment doc)

- [ ] Both streams play correctly in Frigate UI
- [ ] No increase in CPU usage (>5% delta)
- [ ] No stream disconnections
- [ ] Stream startup time equal or faster than h264

### Failure Criteria

- Stream fails to play in Frigate
- go2rtc logs show parsing errors
- CPU usage increases significantly
- Recording corruption

## Important Context

- Pi 5 has NO hardware H.264 encoder -- uses software x264 via libav
- `--low-latency` suppresses B-frames (Pi 5 specific, critical for streaming)
- `--intra 15` = 1-second keyframe interval at 15fps (Frigate recommended)
- go2rtc uses lazy process spawning -- rpicam-vid only runs when a client consumes the stream
- RPi camera docs recommend mpegts over raw h264 for streaming
- go2rtc's exec pipe transport supports MPEG-TS natively
- Frigate receives RTSP from go2rtc regardless of pipe format -- no Frigate config changes needed
- DO NOT use VSCode Remote on the Pi (causes CPU exhaustion crashes)
- The ExecStartPre=/bin/sleep 60 causes ~60s delay on every go2rtc restart
