Hard Rules Learned the Hard Way

H.264 only
H.265 hardware encode → kernel panics on Pi 5. Permanently abandoned.
KillMode=control-group in systemd
Without it, parent restart leaves zombie rpicam-vid processes.
rpicam-vid direct exec
No ffmpeg pipes — single process, no broken pipe cascades.
apt-mark hold Docker
Prevents surprise Frigate restarts from GUI auto-updater.

Every rule traces to a specific incident report in the vault.

§ 3
Python Session Daemon

Daemon Architecture & Data Flow

Key Design Decisions

1. Autonomous core
If the daemon crashes mid-session, Frigate keeps recording. MQTT state persists ON. No data loss.
2. Metadata optional
Missing metadata → unknown. Recording still happens, still exports.
3. Multi-chamber independent
4 chambers run in parallel, each with its own state & pending metadata.
4. Observer-only
The daemon never controls Radiens. The researcher stays in charge.

Synchronization

1 s
Radiens poll interval
±2 s
Export timestamp buffer
4 ch
Independent state machines

Honest limitation: software-level sync, good for behavioral analysis.
Not sufficient for ms-level spike-to-frame alignment. See § 7 for the hardware upgrade plan.

How the Reserve Is Enforced

  • Background thread samples disk every 30 s via os.statvfs() (single syscall, ~0 ms)
  • Atomic dict swap → API thread never reads partial data
  • Category scans (exports / recordings / clips) cached 5 min
  • can_start_recording() returns False if available < 200 GB
  • Bitrate sync button — live-queries go2rtc on both Pis, parses --bitrate from rpicam-vid exec
