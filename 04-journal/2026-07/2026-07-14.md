# 2026-07-14 — Post-processing QC of the 72h run and yesterday's 8-headstage run

> [!abstract] TL;DR
> I post-processed two recordings, the 72 hour four-mouse run (`uid0710-08-53-31`, Friday to Monday 9am) and yesterday's 20 hour eight-headstage run (`uid0713-12-59-49`, Monday 1pm to Tuesday 9am). Both are UNUSABLE and NOT scoreable. Every channel on both files is dominated by 60 Hz mains hum (53 to 88 percent of raw power), and after I comb-notch the hum out the residual is still 0.5 to 1.9 millivolts, which is 5 to 20 times too noisy for real mouse electroencephalography (EEG). The root cause is the same floating-ground problem the 72h audit already flagged on 2026-07-13, the earthing fix was NOT applied before either recording. A faint sleep/wake structure survives on a few channels (slots B and A on the 72h file, B1/B2/D1 on yesterday's), which tells me those electrodes ARE making real contact, but the signal-to-noise ratio is far too low to score.
>
> On the "which mouse is which cable" question for yesterday's run, I CANNOT answer it from the data. Because the whole system floats, an open unconnected input hums just as loudly as a connected electrode, so the four connected mice do not stand out cleanly. That has to be resolved physically at the rig.

## Index — how I got to the verdict (thought flow)

1. **Located the files.** Three `.xdat` sets in `~/radix/data/`. Confirmed which is which from sample count and start time, not the filename alone.
2. **Read the metadata, not just the data.** The `.xdat.json` carries a full `biointerface_map` (channel names, native index, port, `is_selected`). That told me the exact channel layout and how many mouse-slots were armed, WITHOUT guessing.
3. **Realised the files are too big for random access memory (RAM).** 272 GB and 75 GB versus 30 GB of RAM. The existing `qc_report.py` loads the whole file, so it would have crashed. I wrote a memory-mapped scanner instead.
4. **Wrote `multimouse_scan.py`.** It samples windows spread across the whole recording and scores every mouse-slot for hum, rail, and physiological content. This is the new code, everything else is existing toolkit.
5. **Ran the fast table first** (no plot), saw all slots flagged as hum-dominated.
6. **Generated the overview plots** to get the definitive test, does any channel show sleep/wake cycling over time.
7. **Interpreted.** Same floating-ground disease on both files. A few channels carry faint real structure, none are scoreable.

## Code I used, and why

Everything ran in the analysis virtual environment `/home/skimlab/eeg-analysis-venv` (numpy, scipy, matplotlib). Scripts live in `02-procedures/eeg-data-analysis/scripts/`.

### Existing toolkit (unchanged)
- **`xdat_io.py`** — the numpy-only reader for the three-file XDAT set. I used it to confirm the format but NOT to load these files (see below).
- **`qc_report.py`** — the standard single-mouse quality-control report. I did NOT run it here because (a) it assumes the single-mouse channel map (natives 0-3 only), and (b) it loads the entire file into RAM with `np.fromfile`, which would have blown up on a 272 GB file with only 30 GB of RAM.

### New code I wrote: `multimouse_scan.py`
Saved into the vault at `02-procedures/eeg-data-analysis/scripts/multimouse_scan.py`. It exists because I needed to scan MANY mouse-slots across HUGE files without the mapping being known in advance.

What it does, step by step:

1. **Memory-maps the data file** with `np.memmap` instead of loading it. Shape is (samples, 262). This means only the little windows I actually touch get pulled off disk into RAM, so a 272 GB file scans in under a minute.
2. **Samples windows spread across the whole recording.** For the summary table it reads 40 windows of 20 seconds each, evenly spaced start to end, so the numbers reflect the whole run (day and night), not one lucky minute.
3. **For each mouse-slot it computes, per channel:**
   - root-mean-square (RMS) amplitude and peak-to-peak, in microvolts,
   - percent of samples sitting at the amplifier rail (±6.39 mV on the RHD2216 chip), which flags an OPEN or floating electrode.
4. **Builds the EEG bipolar derivation** (frontal minus parietal) and measures:
   - the fraction of power in the 58-62 Hz band, RAW, which is the mains-hum load,
   - the same fraction AFTER a comb notch filter that removes 60 Hz and every harmonic up to Nyquist,
   - the fraction of power that lands in the physiological 0.5-40 Hz band after the notch, which is my proxy for "is this actually brain".
5. **Classifies each slot** as DEAD, HUM, MARGINAL, or USABLE from those numbers.
6. **Overview plot per slot** (the real test): the EEG spectrum raw versus notched, the theta/delta ratio sampled once per minute across the whole recording, and the EMG tone over time. If a channel carries real sleep, the theta/delta ratio CYCLES between sleep and wake and the EMG drops in sleep. If it is noise, both are flat.

Reasoning for the notch-then-measure approach: 60 Hz on its own can be filtered, so the honest question is not "is there hum" but "once I remove the hum, is there enough clean brain signal left to score". That is what the residual RMS and the physiological fraction answer.

Commands:
```bash
PY=/home/skimlab/eeg-analysis-venv/bin/python
cd ~/Monitoring_project/.../02-procedures/eeg-data-analysis/scripts
$PY multimouse_scan.py /home/skimlab/radix/data/allego_0__uid0713-12-59-49 eight
$PY multimouse_scan.py /home/skimlab/radix/data/allego_0__uid0710-08-53-31 four
```

## Interpretation

**The dominant finding is identical on both files: a system-wide 60 Hz mains hum sitting on every channel.** Korea mains is 60 Hz (confirmed 2026-07-05), and the hum is 53 to 88 percent of the raw power. This is not a per-electrode problem, it is the whole rig floating with nothing tied to earth.

**The comb notch removes the 60 Hz line but does not save the recording.** After notching every harmonic, the leftover EEG is still 0.5 to 1.9 millivolts RMS. Clean mouse EEG, once filtered, should be under about 300 microvolts. So even with the hum line gone, the channels are still 5 to 20 times too noisy. The physiological-band fraction is only 4 to 31 percent, meaning most of what is left after the notch is STILL broadband electromagnetic interference, not brain. A clean channel would be well over 70 percent physiological.

**Why the notch cannot rescue it:** as the 2026-07-13 audit found, the hum is partly DIFFERENTIAL, it appears differently on the two EEG pads, so the bipolar subtraction does not cancel it and neither does a notch. That only happens when the reference is floating rather than earthed.

**There IS real brain signal underneath.** On the 72h file, slot B (and more weakly A) shows a clear theta/delta ratio cycling over the three days, and the EMG shows active/rest blocks. On yesterday's file, B1, B2, and D1 show the same faint sleep/wake structure. That structure proves those electrodes are making genuine contact with the animal. The problem is purely that the hum buries them. If the grounding is fixed, these mice would very likely give scoreable data.

**Slots C and D on the 72h file, and A2/C1/C2 yesterday, are flat noise** with a high uniform spectrum floor. Those are either floating open inputs or badly-grounded contacts. No usable structure.

## The "which mouse is which cable" question (yesterday's run)

I CANNOT resolve this from the data, and here is why: because the entire system floats, an OPEN unconnected headstage input picks up just as much 60 Hz hum (2 to 5 mV) as a connected electrode does. So the four unconnected slots do not read as dead or quiet, they read as hum, exactly like the connected ones. There is no clean signature that separates connected from unconnected under these conditions.

The best I can do is rank the slots by how much physiological structure survives, which is a soft hint at which are real electrodes on real animals:

**Most likely real contact → least:  B1, B2, D1  >  A1, D2  >  A2, C1, C2.**

But this must be confirmed physically at the rig by tracing the cables. Do NOT trust the ranking as a channel-to-animal map.

---

## Root cause and fix

Same conclusion as the 72h audit. The rig is a FLOATING system, nothing is tied to EARTH (the mini-PC is 2-prong), so common-mode mains couples in and partly converts to a differential signal that bipolar and notch cannot remove.

**FIX, before any further recording:** one earth wire from the board ground to an earthed desktop PC case, single point, bond the rack, and live-test the hum on the Allego display BEFORE committing to a long run. Procedure is in `02-procedures/earthing-60hz-hum-fix.md`.

> [!warning] Until the earthing fix is applied and live-verified, every recording is wasted. Both of these multi-day runs produced ZERO scoreable EEG for exactly this reason.
