## Work Log

### Docker Packages Pinned Against Unattended Upgrades

**Problem:** A system-wide `apt upgrade` updated Docker, which restarted the Docker daemon and the Frigate container. On restart, Frigate's config has `record.enabled: true`, so all 4 cameras immediately began recording — wasting storage and creating orphaned recordings outside any session.

**Root cause analysis:**
- Frigate config (`/srv/frigate/config/config.yml`) sets `record.enabled: true` globally and per-camera
- On container restart, Frigate reads this config and starts recording immediately
- The session daemon publishes OFF via MQTT on startup, but Frigate reasserts ON from its config within seconds
- The daemon's 10-second grace period was designed for this — it ignores the reassertion rather than fighting it
- Net result: cameras always end up recording after any Frigate restart

**Decision:** Keep `record.enabled: true` (fail-safe design — never lose video if daemon crashes mid-session). Instead, prevent the trigger: pin Docker packages so they never auto-update.

**Fix applied:** Added Docker packages to unattended-upgrades blacklist in `/etc/apt/apt.conf.d/50unattended-upgrades`:

```
Unattended-Upgrade::Package-Blacklist {
    // Docker packages - prevent automatic updates that restart containers
    "docker-ce";
    "docker-ce-cli";
    "containerd.io";
    "docker-compose-plugin";
    "docker-buildx-plugin";
    ...
};
```

**Current pinned versions:**
- Docker CE: `5:29.3.0-1~ubuntu.24.04~noble`
- Docker Compose: `v5.1.0`
- Frigate image: `ghcr.io/blakeblackshear/frigate:0.16.1` (already pinned in `docker-compose.yml`)

**Update procedure going forward:**
1. Stop cameras (turn off recording in Frigate UI or via daemon)
2. `sudo apt update && sudo apt upgrade docker-ce docker-ce-cli containerd.io`
3. Verify Frigate comes back: `docker ps`
4. Confirm cameras are not recording: check Frigate UI
