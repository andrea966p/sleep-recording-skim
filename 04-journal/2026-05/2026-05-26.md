## Observation — too-short manual stops leave no WAL terminal event

WAL scan since Mon surfaced 4 manual sessions (all 4 cams, `START` 12:25:27 May-25, `STALL` 12:26:01) with **no** `EXPORT_COMPLETE`/`ABORT`. Root cause: `manual_session_manager.stop_recording()` (line ~179) takes the *"too short (<min_duration), ignoring"* path for sub-threshold recordings and returns without writing a terminal WAL event. So a too-short manual recording leaves a dangling `START`. Benign here (test residue), and reconciler correctly did **not** STUCK-flag them, but it is a real WAL-completeness gap: an aborted-because-too-short session has no closing event. **Phase 6 nit** — consider writing an `ABORT`/`TOO_SHORT` terminal event on that path so the WAL lifecycle is always closed.
