## Work Log

### Moved my day to day work off the recording machine, onto the ThinkPad

`e10ubuntu` is the machine that runs the recordings, so I stopped using it as my desk.
Work now happens on the ThinkPad laptop and I reach the rig over SSH. Three things had to
be true and all three now are: the vault syncs to the laptop, Claude Code has the same
memory and skills there, and I can run commands on `e10ubuntu` without opening a remote
desktop session. Full writeup with the numbers is in
[[01-infrastructure/multi-machine-work-setup]]; this entry is the short version.

While setting it up I found what almost certainly killed the vault the last time. The
Syncthing folder had **NO FILE VERSIONING**, so a delete on any machine propagated
everywhere with zero undo, and it had **NO IGNORE RULES**, so the live 114 MB `.git`
directory was being copied between machines while the obsidian-git plugin committed into
it on both ends. Both are fixed now: staggered versioning with 365 day retention, and
`/.git` excluded through a `.stignore` file. I tested it rather than assuming: a delete on
the laptop propagated in about five seconds AND left the whole file recoverable in
`.stversions/` on `e10ubuntu`. That is the exact operation that destroyed the vault
before, and it is now survivable.

### Both repositories pushed, laptop verified

Pulled `~/claude-portable` on the laptop, the shared Claude Code config repository holding
memory, skills, hooks and settings. It reported **Already up to date** at commit
`d8beef4`, which is correct because the laptop is where those commits were made.
`check.sh` reports all nine symlinks healthy, the memory index loads with 56 files, and
the caveman hooks fire on session start and on prompt submit.

### Untangled two vault directories on the laptop

I had the vault twice on this machine and opened both by mistake, which was confusing
because their contents were identical.

- `~/Monitoring_project/Monitoring_project_obsidian_vault` is the **live** one. Syncthing
  manages it, versioning is on, `.stignore` excludes `/.git`.
- `~/Projects/Monitoring_project_obsidian_vault` is a **git clone** of
  `andrea966p/neurosurveillance-vault`. Syncthing does not touch it. Its HEAD `e770479`
  is `e10ubuntu`'s auto backup from 01:10 last night, so it already contained everything.

`diff -rq` across both trees found **no note present in one and not the other**, and the
clone had no uncommitted changes and nothing unpushed, so there was nothing to rescue.
Fixed by removing the clone from Obsidian's vault list (its files were left on disk) and
deleting its leftover `.stfolder` marker. I also deleted a stale sync conflict copy of
`04-journal/2026-04/2026-04-13.md` after checking it was a strict subset of the live note,
missing the 2026-08-14 correction callout. The delete propagated to `e10ubuntu` and landed
in `.stversions/` there, which is the safety net proving itself a second time.

**⚠️ The risk here was never lost data, it was that edits made in the clone go nowhere.**
It looks live because the content is current, but nothing syncs out of it.
