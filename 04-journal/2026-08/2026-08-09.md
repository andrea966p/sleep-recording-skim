## New recording started at 09:00:00 sharp

**`allego_0__uid0809-09-00-00`, started 2026-08-09 09:00:00.07 KST.**

⭐ **09:00 is lights ON, which is ZT0.** This recording therefore begins **exactly at the top of
the light phase** and will give a clean, complete light then dark cycle. The previous run started
at 16:17, part way through the light phase, which made the circadian comparison awkward. **Prefer
a ZT0 start for every long run from now on.**

Verified the reliable way, by watching the destination: `_data.xdat` grew from 0 bytes and is
still growing. **680 GB free**, and at roughly 3.9 GB per hour a 24 hour run needs about 94 GB.

Started with a new helper, **`eeg-emg-analysis/qc/start_recording_at.py HH:MM:SS`**, which waits
for the wall clock, sets the recording configuration using the workaround for the broken library
call, turns streaming on 20 seconds early so the amplifiers are settled, fires
`set_recording('on')` at the target instant and then **verifies by watching the destination
directory grow** rather than by trusting the client.

⚠️ Both standing Allego traps are handled inside that script and both still apply to anything
else you write: **`set_recording_config()` is broken** (required `recordingType` enum never set,
fails with `Exception serializing request!`), and **`get_status().recording.path` reports the
client process's working directory, not the output directory**.
