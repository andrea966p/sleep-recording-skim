## Work Log

### Fixed: Can't delete exported video recordings

**Problem:** Exported videos in `/srv/frigate/storage/exports/` were undeletable. The daemon organized exports into `{user}/{mouse}/{date}/` subdirectories inside the Docker volume, but all directories were root-owned (created by `sudo mkdir -p`). Linux requires write permission on the parent directory to delete files, so even chowned MP4s were trapped.

**Root cause:** The config set `export_dir` to `/srv/frigate/storage/exports` (Docker volume, root-owned), using it as both the Frigate source and organized target. The `chown -R` call in `daemon.py` silently failed because sudoers didn't allow the `-R` flag.

**Fix applied:**
1. Separated source and target paths in `daemon.py`:
   - `export_source_dir`: `/srv/frigate/storage/exports` (Frigate Docker volume, read-only)
   - `export_dir`: `/opt/neurosurveillance/exports` (skimlab-owned, user-deletable)
2. Replaced `sudo mkdir -p` with `Path.mkdir()` (no sudo needed -- target dir is skimlab-owned)
3. Removed broken `chown -R` call
4. Updated `config.yaml` with new `export_source_dir` key
5. Updated sudoers: removed `mkdir` from allowed commands
6. Moved existing exports from Docker volume to `/opt/neurosurveillance/exports/` and chowned

**Files changed:**
- `neurosurveillance/backend/daemon.py`
- `config/config.yaml` + production copy on NVR
- `/etc/sudoers.d/neurosurveillance-fs` on NVR
