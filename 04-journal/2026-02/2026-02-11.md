## Work Log

### External Analysis Review

Reviewed a comprehensive analysis comparing the vault's golden configs against official RPi camera documentation and go2rtc upstream docs. The analysis covered go2rtc exec source behavior, rpicam-vid options on Pi 5, Frigate integration patterns, and systemd service configuration.

**Key finding from the research:** Pi 5 has **no hardware H.264 encoder**. It uses software encoding (x264 via libav). The golden config rules table incorrectly said "Direct hardware encoding" -- fixed.

**Key finding from RPi docs:** Three rpicam-vid flags were missing from the production config:
- `--low-latency` -- suppresses B-frames on Pi 5 (software encoder generates B-frames by default, which can break streaming clients)
- `--intra 15` -- sets keyframe interval to 1 second (default was 60 frames = 4 seconds at 15fps). Frigate recommends 1x GOP for fast stream startup.
- `-n` -- disables preview window (useless on headless Pi, wastes resources trying to render to nonexistent display)

**What the analysis got right:**
- Part 1 (validations): H.264 path, single-line exec, `KillMode=control-group`, direct stdout, TCP transport, QSV decoding all confirmed correct
- Part 3 (things to avoid): H.265, ffmpeg pipes, gpu_mem ineffectiveness all confirmed

**What the analysis got wrong:**
- Suggested replacing `ExecStartPre=/bin/sleep 60` with systemd dependencies -- rejected because the 60s delay is for **hardware/electrical** reasons (IR LED power spike prevention during boot), not software timing
- The "hardware encoding" label in the rules table (contradicted its own findings)

### Core Technical Concepts Learned

1. **Pi 5 software encoding:** Pi 5 has no dedicated H.264 hardware encoder (unlike Pi 4). The `--codec libav` path uses x264 software encoding via ffmpeg/libav backend. This is why CPU usage is higher than expected and why `--low-latency` exists specifically for Pi 5.

2. **B-frames on Pi 5:** The software encoder generates B-frames by default (Pi 4's hardware encoder did not). B-frames improve compression but cause issues with streaming formats. `--low-latency` suppresses them and also disables arithmetic coding, trading slightly worse compression for significantly better streaming compatibility.

3. **Keyframe interval matters for Frigate:** The default `--intra 60` meant a keyframe every 4 seconds at 15fps. Frigate must wait for a keyframe to start decoding. Setting `--intra 15` (= 1 keyframe/second) dramatically improves stream startup time and recovery after network glitches. Frigate docs explicitly recommend matching GOP to framerate.

4. **go2rtc pipe transport:** go2rtc's exec source reads H.264 bitstream (or MPEG-TS) from stdout via pipe transport. It also supports `#starttimeout=N` parameter (added in v1.9.14) and `#killsignal=N` / `#killtimeout=N` for process lifecycle management.

5. **MPEG-TS vs raw H.264:** Raw H.264 bitstream lacks container-level framing and timestamps. MPEG-TS wraps the stream with proper packet boundaries and timing info. RPi docs recommend MPEG-TS for all streaming scenarios. This is worth testing but should not be changed in production without validation.
