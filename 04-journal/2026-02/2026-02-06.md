### RustDesk Lag Troubleshooting & Resolution

**Problem:** Severe lag when connecting from PC1 to e10 via RustDesk, despite excellent network (1.7ms latency).

**Investigation:**
- Checked NAS relay server (bilab-syn at 100.120.86.10)
- Found RustDesk services running but only listening on IPv6 (not IPv4)
- Both PCs were configured to use NAS as relay server, causing constant RST errors
- High Send-Q (7.9KB) on direct P2P connection indicated encoding bottleneck

**Root Cause:**
1. RustDesk trying to use broken relay server on NAS (IPv6-only binding)
2. VA-API video encoding issue after Mesa 25.2.8 update (Feb 3rd)

**Solution Applied:**
1. Set up SSH key access to NAS (port 53)
2. Configured RustDesk for **direct P2P only** (removed relay server from config)
   - PC1: `~/.config/rustdesk/RustDesk2.toml`
   - e10: `~/.config/rustdesk/RustDesk2.toml`
3. Updated VA-API libraries on e10 (libva2 2.20.0-2ubuntu0.1)
4. Updated kernel to 6.17.0 (better Intel Arc support)
5. Rebooted e10

**Result:**
- ✅ Send-Q now 0 (was 7.9KB) - bottleneck resolved
- ✅ Lag significantly reduced/eliminated
- ✅ Direct P2P connection stable via Tailscale
- ⏳ RST errors decreasing (cached connections timing out)

- Config backups: `~/.config/rustdesk/RustDesk2.toml.backup` on both PCs
