# 2026-06-26

> [!abstract] Purpose
> Switched the whole rig to the **8-channel slip-ring / 8-pin tether** standard and tried the **grounding-bus** GND fix. Two headstages in play today. **Result: (A) the single-mouse headstage will not enumerate, root cause still open; (B) a separate 2-mice+ECG headstage enumerates but the grounding bus is NOT working — animals still floating.** Both items carry to tomorrow (operator out of the building). Grounding guide: [[signal-quality-and-grounding]]. Detection playbook: [[first-headstage-connection]].

## Standardization decision
**8-channel system is now the standard for everything going forward.** Swapped tether → 8-pin socket on the slip-ring side. New grounding scheme = **animal ground wire → grounding busbar → one wire → C3410 `GND` pad** (the green/orange animal-ground is NOT on a signal pad anymore — that was the old defect).

## Setup A — single-mouse headstage: NOT DETECTED (open, revisit tomorrow)

One mouse (the other died), same headstage as before, on **the second SPI socket** of the SAdpt-XDAQ-OM12 bridge. Only physical change vs the last-working 06-22 state: soldered a **GND socket onto the C3410 `GND` pad** + wire to busbar, swapped to the 8-pin tether. Adapter-board color map: `0` EEG red, `1` EEG black, `2` EMG yellow, `3` EMG blue, **green = animal ground → busbar (not on a board pin)**. Mouse copper-tinned coil matched with green.

**Symptom:** `port_num_channels = {}`, `priSigs=0` on every port scan. Headstage never enumerates.

**Eliminated today (exhaustive):**
- ✅ **Allego mode correct** — `XDAQ_ONE_REC` confirmed in SDK + allegoserver log (NOT the 06-19 SmartBox-Pro trap; that was checked and ruled out — mode did silently revert to `SMARTBOX_PRO` once after an Allego relaunch, restored to `XDAQ_ONE_REC`).
- ✅ **XDAQ core healthy** — USB SuperSpeed 5 Gbps (`151f:0130`), FPGA configured, onboard I/O enumerates (`auxSigs/dinSigs/doutSigs=2`, `Fs=30000`), actively auto-detecting.
- ✅ **Bus power present** — DMM at headstage VDD↔GND while streaming = **3.57 V** (matches 06-19's 3.56 V; top of Intan 3.2–3.6 V spec). Power pins of the SPI connector are good.
- ✅ **No VDD↔GND short** — resistance check open (`1` on 2k range; the transient `575` seen earlier was beep/diode mode = cap charge, no beep = no short).
- ✅ **Ground rewire excluded** — tested **bare headstage, SPI cable only, electrode/busbar/ground fully disconnected**, correct mode, power confirmed → still `priSigs=0`. So the new grounding bus is NOT what blocks detection.
- ✅ Swapped headstage, both C3026 cables, both SAdpt adapters, front-panel ports 1 + 4, full power-cycle, **PC restart**.

**Where it stands:** power-good + correct-mode + bare-SPI + everything-swapped + still `priSigs=0`. SPI **power+ground pins work** (3.57 V), so the fault is in the SPI **signal** path (SCLK/CS/MOSI/MISO) — either this headstage's SPI Omnetics (bent/recessed **signal** pin from the slip-ring/ground handling right next to it) or the XDAQ SPI subsystem on **that** bridge socket.

> [!note] Strong clue — it's socket-specific
> Setup A failed on the SAdpt's **second** SPI socket; Setup B (below) **enumerates fine on the other socket** of the same bridge, same XDAQ, same mode. So XDAQ-core-wide death is unlikely — points at **the Setup-A headstage's SPI connector** or **that specific SAdpt socket / its HDMI path**.

**TOMORROW — decisive test (do cleanly, bare-SPI-only, power-confirmed):**
1. **Spare headstage, bare, SPI-only**, same C3026/SAdpt **socket**, correct mode → probe.
   - Spare detects → the in-use headstage's SPI connector is damaged (inspect Omnetics for a bent **signal** pin under magnifier).
   - Spare also `{}` → that SAdpt socket / HDMI path → swap to the **known-good socket** (the one Setup B uses) to confirm, else vendor (KC Kong / Kontex).
2. Magnifier-inspect the suspect headstage's SPI Omnetics vs a good one.

## Setup B — 2 mice + ECG headstage: DETECTED, but grounding bus NOT working

Separate headstage, **2 mice**, on **the other SPI socket ("Port 1")** of the same HDMI bridge. Detected: **Port A, 32 ch, `XDAQ_ONE_REC`, streaming.** Each mouse has EEG + EMG + **ECG**. New design: **orange = animal ground → busbar → C3410 `GND` pad.**

Adapter-board map (per mouse): `0` EEG+ red, `1` EEG− black, `2` EMG+ yellow, `3` EMG− blue, `4` ECG+ green, `5` ECG− brown, **orange = GND → bus**. Mouse 2 from native `8` (8–13 same order).

**Raw signal metrics** (no bandpass — raw first, per [[signal-quality-and-grounding]]; `signal_metrics().get_metrics()`, `np.NAN` shim):

| native | `D/n` | signal | RMS µV | pk-pk µV | verdict |
|---|---|---|---|---|---|
| 0 | D/1 | M1 EEG+ | 2964 | 12486 | 🔴 railed |
| 1 | D/2 | M1 EEG− | 159 | 1511 | ok |
| 2 | D/3 | M1 EMG+ | 289 | 1412 | ok |
| 3 | D/4 | M1 EMG− | 2498 | 12229 | 🔴 railed |
| 4 | D/5 | M1 ECG+ | 2254 | 12642 | 🔴 railed |
| 5 | D/6 | M1 ECG− | 2505 | 12013 | 🔴 railed |
| 8 | D/9 | M2 EEG+ | 2266 | 9899 | 🔴 railed |
| 9 | D/10 | M2 EEG− | 2282 | 12088 | 🔴 railed |
| 10 | D/11 | M2 EMG+ | 2295 | 9626 | 🔴 railed |
| 11 | D/12 | M2 EMG− | 1044 | 8966 | 🟡 elevated |
| 12 | D/13 | M2 ECG+ | 2806 | 11393 | 🔴 railed |
| 13 | D/14 | M2 ECG− | 1049 | 10082 | 🔴 railed |

- Amp window ±5 mV (≈10 mV pk-pk max). **10/12 channels railed at 10–12.6 mV = animals floating.** Same fingerprint as pre-grounding 06-22.
- **Both mice railed together** → they share one tie (bus → `GND` pad → chip GND). If that common tie were good, animals would sit in-window. Everything railing ⇒ **the common ground tie is broken.**
- The 3 survivors (M1 EEG−, M1 EMG+, M2 EMG−) ride stray coupling, not real grounding (cf. M1 partial survival 06-22).

**Conclusion: the grounding busbar is not electrically reaching chip GND.** Prime suspect = **cold joint on the socket freshly soldered to the C3410 `GND` pad** (connects mechanically, not electrically).

**TOMORROW — DMM continuity the ground chain** (resistance 2k / beep), each link must be **~0 Ω**:
1. **Busbar screw ↔ C3410 `GND` pad** (across the new solder joint) — *prime suspect, test first.*
2. C3410 `GND` pad ↔ headstage GND (through the board↔headstage connector).
3. Orange animal-ground wire ↔ busbar screw.
4. End-to-end: animal-ground ↔ chip GND.
Any link reading `1` (open) = the break. Re-flow the GND-pad joint if link 1 is open, then re-check raw metrics (railing should collapse to in-window).

## Tools / SDK notes
- Live probe: `/opt/neurosurveillance/venv/bin/python -c "from radiens import AllegoClient; print(AllegoClient().get_status().port_num_channels)"`.
- Port-scan truth: `grep priSigs ~/.local/state/radiens/logs/allegoserver.log | tail` — sweeps all ports A–H at once, so front-panel port doesn't matter for detection; `priSigs=0` = no chip answering anywhere.
- Metrics need the `np.NAN=np.nan` shim (radiens 4.0.0 + NumPy 2.x). Array `(1,32,6)`: RMS, NOISE_UV, MAX_MIN_DIFF_ABS, SNR, EVENT_RATE, EVENT_MEAN. `MAX_MIN_DIFF_ABS` ≈ 10–12 mV = railed.
- `HAL:cc22 "unable to send to listener"` warnings in allegoserver.log = MQTT stream-subscriber noise, **unrelated to SPI/detection** — ignore.
