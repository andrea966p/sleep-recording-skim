## Task 1 — First headstage bring-up ✅ RESOLVED
Carried over from 2026-06-18. **Solved this afternoon — headstage detected, streaming shows signal.** `port_num_channels={<Port.D:3>:32}`, `priSigs=32`, `mode=XDAQ_ONE_REC`.

**Root cause = wrong Allego system mode**, not hardware. Allego was on `SMARTBOX_PRO`; correct mode for this unit = **"XDAQ One (G1) with XR Headstage"** (`XDAQ_ONE_REC`). Switching modes → instant detection. Hardware was healthy the whole time.

The morning's teardown (DMM, swaps, ports) chased a hardware false-trail — but it *did* prove the hardware good, which forced the mode realization:
- **DMM** at headstage VDD↔GND while streaming = **3.56 V** (validated on-pad; a first air-float misread of 3.33 V disregarded) → bus power good, not a power fault.
- Brand-new **SAdpt-XDAQ-OM12**, brand-new **spare headstage**, Ports **1/3/4** + firmware-wait + Allego restart — all still `priSigs=0` under the wrong mode.
- Lesson: `SMARTBOX_PRO` shares the `IntanUSB3Instrument` USB3 backend, so it *connects + scans + enumerates GPIO* but reports `priSigs=0` for the wrong headstage profile. **Controller-connects ≠ correct-mode.** Kontex's "verify an XR-type headstage" hint pointed here.

**Escalation emails were drafted ([[first-headstage-connection]] §11) but NOT sent — no RMA, no vendor escalation.**

**Before real recordings:** (1) C3410 **solder reflow** (messy joints); (2) **sample rate** — mode switch reset it to 1000 Hz, restore 30 kHz; (3) use **`Stream` not `Record`** for checks (Record triggers the session daemon → Frigate session); (4) GND/REF still skipped → expect hum/saturation until bridged. Do **not** add the C3442 splitter — both mice share one headstage via the C3410 channel map.
